## 修 bug：内嵌小游戏结算遮罩遮挡底部按钮（v1.0.36）
用户反馈：围住神经猫(sjmao) 的失败/胜利结算遮罩把底部「返回/新游戏」按钮挡住（但按钮仍能按到）；并称暴打神经猫(bdsjm)、全民寻找房祖名(qmxz) 之前也出现过，要求一并排查后面添加的 10 款小游戏。

### 根因
按钮在 draw 函数**开头**先绘制，结算遮罩用**全屏** `ctx.fillRect(0, 0, screenWidth, screenHeight)` 在结尾覆盖，把按钮视觉盖住。点击逻辑基于坐标 `inRect`，与绘制层级无关 → 按钮"还能按到"。

### 统一排查 13 款内嵌小游戏（drawMiniGame*）的结算遮罩
| 游戏 | 遮罩写法 | 按钮 | 结果 |
|---|---|---|---|
| 2048 | drawMiniGameOverlay 只盖棋盘 | 不挡 | ✅ |
| qmxz/bdsjm | 只盖游戏区 `fillRect(0,0,W,btnTop-8)` | 不挡 | ✅ 此前已修 |
| qiexigua/feidegenggao/bunengsi | 只盖 board 区 | 不挡 | ✅ |
| xnf(小鸟飞飞飞) | 全屏遮罩，但按钮在遮罩**之后**置顶重绘 | 不挡 | ✅ 安全（注释"HUD 始终置顶"） |
| **sjmao/zqyl/qingwa/sqsd/ybh/dlsq** | **全屏遮罩** | **被挡** | ❌ 本次修复 |

### 修复
- 给 6 个函数（drawMiniGameSjmao/Zqyl/Qingwa/Sqsd/Ybh/Dlsq）在 `const L = ...Layout()` 后加 `const btnTop = Math.min(L.backBtn.y, L.restartBtn.y);`
- 把 8 处结算 `fillRect(0, 0, screenWidth, screenHeight)` 改为 `fillRect(0, 0, screenWidth, btnTop - 8)`（qingwa/ybh 各 2 处 win+stuck，其余各 1 处）。
- 注意：Xnf 的 7776 全屏遮罩**故意保留**（按钮置顶重绘，已安全）；主游戏背景的全屏 fillRect 不动。
- node --check 双文件通过；game.js 由副本 cp 同步。commit 9494245，tag v1.0.36，**未推送**（等用户指令）。

### 经验（可复用）
内嵌小游戏结算遮罩标准二选一：
1) 遮罩只盖游戏区，留底部按钮栏：`ctx.fillRect(0, 0, screenWidth, btnTop - 8)`；
2) 全屏遮罩时，按钮必须在遮罩**之后** `drawMiniGameButton(...)`（如 xnf 的 HUD 置顶写法）。
避免"按钮先画 + 全屏遮罩后盖"的组合。

## 优化：大力射手（dlsq）球位置 + 背景（v1.0.37）

### 注意

## 修 bug：大力射手弹弓随球移动（v1.0.38）
用户反馈：刚加的弹弓会跟着球一起移动，不需要跟着动。

### 根因
弹弓绘制用 `sx = g.startBall.x`（固定屏幕坐标，忽略 camX）。飞行时镜头跟随球（`camX = max(0, ball.x - 0.45*boardW)` 使球停在屏幕固定处），弹弓也停在原地、紧贴球，看起来像"跟着球一起移动"。

### 修复
- `sx` 改为 `g.startBall.x - camX`（与地面/km 标记一致的世界坐标）。飞行时弹弓随地面一起向左滚出屏幕，球因镜头跟随留在原地，二者明显分离。
- aim/拖动时 camX=0，弹弓与球同位于起点、皮筋正常连接，行为不变。
- node --check 双文件通过；game.js 由副本 cp 同步。commit c27df1c，tag v1.0.38，**未推送**（等用户指令）。

## 环境坑（重要）：GitHub 推送需代理/VPN 开启
- 本机 `C:\Windows\System32\drivers\etc\hosts` 被某代理/VPN 工具写入大量 `127.0.0.1 github*.com`（含 `github.com`）映射。代理/VPN **关闭**时，git 把 github.com 解析到 127.0.0.1、且真实 IP 20.205.243.166:443 也无直连路由 → `git push` 必失败（Connection reset / Could not connect）。
- 之前 v1.0.27~v1.0.35 能推送，是因为那时代理/VPN 开着。
- **结论**：推送前必须先开启访问 GitHub 的代理/VPN（系统代理/TUN 模式）。不要擅自改 hosts（系统文件，且直连本就到不了）。用户已确认「去开启代理/VPN」后重试。

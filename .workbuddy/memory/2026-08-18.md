## 天赋升级弹窗 UI 优化（v1.1.49）

用户截图反馈弹窗有三个问题：
1. 标题显示 "root_wall"（英文 effect 键）而不是中文。
2. 升级按钮里金币与"升级"二字重叠。
3. 整体排版不够清晰。

### 根因
1. 大标题：弹窗顶部 `case b[13]` 渲染 `T["icon"]`（= effect 键），`case 1` 渲染 `"效果: "+T["effect"]`，中文名 `T["name"]` 反而在中间位置（`case b[10]`），视觉层级错乱。
2. 按钮重叠：`case b[49]` 把 `fU+T["cost"]` 画在按钮内部 `Q+X-8`（按钮底部），与 `drawRoyaleBevelButton` 自带的"升级"标签中心位置撞在一起。

### 修复
1. `case b[13]`：`T[d[2]]`（icon 键）→ `T[F]`（name，中文），顶部大标题变成节点中文名。
2. `case 1`（副标题）：用 effect 键前缀映射成中文分类——
   - root_* → 根脉
   - coeff_* → 属性加成
   - elem_def_* → 元素防御
   - elem_hp_* → 元素生命
   - elem_crit_* → 元素暴击
   - unlock_* → 解锁门
   - syn_* → 协同
   不再显示生硬的 "root_wall"。
3. `case b[49]` 可升级分支：把"🪙 40"从按钮内部 `Q+X-8` 移到按钮上方 `Q-18`，加"需要"前缀 + 金色 `e[0]=#ffd700`，按钮里只剩干净的"升级"。

### 验证

- Node 模拟分类：root_wall→根脉 / coeff_火→属性加成 / elem_def_火→元素防御 / 全部 effect 类型映射正确。
- 提交 + tag **v1.1.49**（不推送）。

## 天赋升级弹窗 UI 二次优化（v1.1.50）

用户截图反馈：第二行重复显示了"根·坚壁"（与标题同名），应是天赋效果说明；"需要 🪙 40"字体太暗（实际是 color key 取错——lM[4][0]="effect" 是字符串不是颜色，导致 fillStyle 无效渲染为暗色）；"已有 🪙 2141"颜色需按金币是否足够变绿/红。

### 修复
1. **第二行改为效果说明**（`case b[10]`）：用 `T.effect` 键映射中文「属性 +数值/级」。映射表覆盖全部 effect 键（root_*/coeff_*/elem_*/unlock_*/def_*/syn_*/critChanceVsCounter/critMultVsCounter/coeffGen_），数值取自 `applyTalentsToBattle` 实际公式（如 root_wall=+20/级、coeff_=+5%/级、elem_def_=+2%/级、coeffGen_火=对土+4%/级）。Node 模拟：root_wall→"墙体血量 +20/级"、coeff_火→"火属性 +5%/级"、unlock_火_3→"解锁火 Lv.3" 等正确。
2. **"需要"字体**（`case b[49]`）：错把 `e[0]`("effect" 字符串) 当颜色用导致暗色——改为 `f[7]="#4fc3f7"`（青蓝，与"已有"同色）。
3. **"已有"按金币足/缺变色**（`case b[2]`）：`haveG3=player["gold"];costG3=T["cost"];fillStyle = haveG3>=costG3 ? "#3ddc84" : "#ff6b6b"`（绿/红）。🪙 emoji 颜色不受 fillStyle 影响，数字与"已有"二字变色。

### 经验
- 混淆代码里 `lM[4][0]` 是字段名 "effect"，不是颜色。颜色用 `lM[5]`（如 `f[7]="#4fc3f7"`、`f[0]="#ffd700"`）。改 fillStyle 之前务必确认 key 是十六进制色串。

## 弹窗升级后不消失 + 需要金币颜色仍暗（v1.1.51）

### 1. 升级后弹窗不消失
handleTalentModalClick `case d[4]` 三个 return 点（claimTalent / 金币不足 toast / 升级成功 toast）都只是 return，没有 closeTalentModal()。用户点"升级"后弹窗一直挂着只看到 "升级成功!" toast。修复：三个 return 前各加 `closeTalentModal();`。

### 2. "需要 🪙 40"颜色还是暗
v1.1.50 改成 `f[7]="#4fc3f7"` 后颜色代码对了但渲染仍暗。根因：drawTalentModal 的渲染顺序（oX 数组）里，case b[47]（全屏半透明暗色遮罩 `ctx[fillRect](0,0,screenWidth,screenHeight)`）在 case b[49]（按钮/费用）之后绘制，把费用文字盖在下面变暗。"类型: 属性加成"在 b[47] 之前所以是亮色。修复：把费用行从 b[49] 的 `if(a){...}` 里删掉，改在**最后一个** case b[44]（关闭按钮）的开头绘制——`if(W&&Q){ctx[q]=f[7];ctx[r]("需要 "+fU+T[I],screenWidth/2,Q-18)}`——保证在遮罩之后绘制，亮色青蓝正常显示。

### 经验
- 弹窗/全屏 UI 的绘制顺序：先放背景与面板，最后放交互信息（费用/提示），避开中途的全屏暗色遮罩。
- v1.1.49→v1.1.50→v1.1.51 三次调"需要"颜色都没真正生效，是因为没找到正确的渲染层级；填色代码对了没用，必须**在遮罩之后**才不被压暗。

### 验证
- `node --check` 双文件 PASS；4 处理一致，长度 667885。
- 提交 + tag **v1.1.51**（不推送）。

## 升级按钮点击后无倒计时（v1.1.52）

用户反馈 v1.1.51 后：需要金币颜色对了，但点升级后弹窗直接消失、天赋没进倒计时。

### 根因
v1.1.51 给成功 toast 后面加的 `closeTalentModal()` 放在了 `if(upgradeTalent(...)){...}` **外面**：
```
if(upgradeTalent(id)){wx[i](toast 升级成功)}closeTalentModal();return
```
→ `closeTalentModal()` 无条件执行。只要 `upgradeTalent()` 返回 false（最常见：另一个天赋正在升级、队列 1 槽已满），弹窗照样关闭，但没扣金币没进倒计时。

### 修复
1. 把 `closeTalentModal()` 移进 `if(upgradeTalent(...)){...}` 内：成功才关框。
2. 失败分支加 toast「已有天赋升级中」（icon=none），弹窗保持打开，避免"点了没反应"。
3. 模拟验证：upgradeTalent(0) 金币 500→460、talentUpgrades[0] 设 3000ms、返回 true；真实代码 `e=c[9]`（c=b[2]=lM[2]→"gold"）、`f=c[12]`="cost"，扣款正确。

### 验证
- `node --check` 双文件 PASS；长度 668013，一致。
- 提交 + tag **v1.1.52**（不推送）。

### 经验
- 给 if 语句后面加语句时，先确认要加在 if 内还是外——v1.1.51 想"成功后关框"，结果 `}` 提前关闭了 if，closeTalentModal 变成无条件执行，把失败路径的框也关了。

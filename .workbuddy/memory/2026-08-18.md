## 失败弹窗崩溃修复（v1.1.54）

用户截图反馈 v1.1.53 失败弹窗"按钮少一个，两个点击都没反应"。

### 根因（致命）
drawGameOver 的 case l 中间按钮绘制块里有一句 **`ctx[s]=eE;`**：
- `s = a[6][0] = lM[6][0] = "fillText"`（已用 vm 跑解码段确认）。
- `eE = "变强"`。
- 所以该句等价于 **`ctx.fillText = "变强"`**——把 canvas 的文本绘制方法永久覆写成字符串。
- 紧接着 `ctx.fillText(eE,...)` 调用字符串当函数 → `TypeError`。更糟：`ctx` 是全局对象，污染对之后**每一帧**都生效，主渲染循环每帧 `ctx[s](...)` 都抛错崩溃。
- 后果：① drawGameOver 在本帧 throw 后，右按钮（返回）未绘制 → "按钮少一个"；② 整个游戏循环卡死 → "两个点击都没反应"。

### 排查要点
- 全文件 `ctx[s]=` 共 9 处；逐一确认 `s` 绑定——只有 drawGameOver 里 `s=a[6][0]="fillText"`，其余 8 处 `s` 绑到 `a[6][17]="duration"`/`b[5]`/`b[3]`（合法 ctx 属性），非 fillText。所以唯一 corruption 在 drawGameOver。
- 同块 `ctx[q]=f[7]` 中 `q=a[7][0]="fillStyle"`、`f[7]=a[3][7]="score"` → `ctx.fillStyle="score"`（非法色，被浏览器忽略，无害空操作），保留无妨。

### 修复
- 仅删 `ctx[s]=eE;`（从 `);ctx[s]=eE;ctx[q]=f[7];` → `);ctx[q]=f[7];`）。三标签（重玩 `b[24]`、变强 `ctx.fillText(eE)`、返回 `b[10]`）保持不变。
- touchend 三按钮坐标已在 v1.1.53 与 drawGameOver 对齐（重玩/变强/返回），无需改。
- 双文件（game.js / 副本.js）同步，长度 2525→2515。

### 验证
- `node --check` 双文件 PASS；`contains ctx[s]=eE: false`；三标签齐全；两文件 drawGameOver 完全一致。
- 提交 `145b71b` + tag **v1.1.54**（不推送）。

### 经验
- 混淆代码里给 `ctx[<var>]=<string>` 赋值时，务必先确认 `<var>` 是不是 `"fillText"`——一旦把 fillText 覆写成字符串，污染是**全局且永久**的，会让整个 rAF 渲染循环每帧崩溃，表现为"整局卡死、点击无反应、某个按钮画不出"。这是比局部 TypeError 隐蔽得多的连锁故障。

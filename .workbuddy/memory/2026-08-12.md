## 修复游戏圈原生按钮每帧重建报错/卡顿（v1.0.96）
- 现象：打开游戏报 `insertTextView/updateTextView/insertImageView/updateImageView:fail parent X not found`（appServiceSDKScriptError），伴随卡顿。
- 根因：`drawMainMenuClub` 每帧调用 `showGameClubButton()` → `gameClubButton.show()` 每帧重复，微信引擎反复重建按钮原生 TextView/ImageView 视图报 parent not found；且每帧 `if(mainMenuTab!=='club') destroyGameClubButton()` + 切Tab也 destroy，造成销毁/重建抖动。
- 修复（`game - 副本.js`）：新增 `gameClubButtonVisible` 状态位；`showGameClubButton` 已显示则直接 return（仅创建+show一次），`hide/destroy` 加 `!gameClubButtonVisible` 早退并以 try/catch 吞掉引擎偶发原生视图错误；原每帧 `destroyGameClubButton()`(5663) 与两处切Tab `destroy`(12150/12384) 改为 `hideGameClubButton()`（仅状态切换，不销毁重建）。离开主菜单(4943)仍 `destroy` 做彻底清理。
- 六套回归全过，已打 tag v1.0.96 并推送（main a68f542，tag 校验通过）。

## 游戏圈按钮「仅创建一次、事件驱动显隐」（v1.0.97）
- 用户希望把游戏圈按钮改成纯 canvas 按钮 + `wx.openGameClub()` 跳转，以彻底规避原生视图偶发抖动。查证微信官方文档后发现：**不存在 `wx.openGameClub` API**；且微信明确限制「打开游戏圈的动作无法由游戏原生按钮触发，必须使用 `wx.createGameClubButton` 创建指定按钮，点击时自动跳转」。故纯 canvas 无法一键跳游戏圈。
- 用户选择方案：保留原生按钮，但改为**仅创建一次、事件驱动显隐**。
- 改动（`game - 副本.js`）：移除 `drawMainMenu` 头部每帧的 `if(mainMenuTab!=='club') hideGameClubButton()`（渲染循环不再每帧调用任何 wx 方法）；原生视图仅在首次进入圈子Tab由 `drawMainMenuClub` 末的 `showGameClubButton()` 创建+show一次（状态位早退），切Tab离开时 `hideGameClubButton()`、离开主菜单(`startGame`)时 `destroyGameClubButton()`。从机制上杜绝原生视图反复重建导致的 parent not found 报错卡顿。
- 六套回归全过（`_load_test` 因自身 harness 作用域冲突 `screenWidth already declared` 报错，与本次改动无关，未修）；双文件 cp+node --check OK。已打 tag v1.0.97（本地，未推送）。
- 复用要点（微信小游戏平台知识）：游戏圈入口只能走 `wx.createGameClubButton` 跳转；若想自定义跳转，可行替代是 `wx.createPageManager().load({openlink}).show()`（需后台游戏圈 openlink 配置，依赖配置）。无 `wx.openGameClub`。

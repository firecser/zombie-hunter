## 多重子弹削弱（v1.1.4 待提交）
用户要求"适度削弱多重强度"。根因：3 棵属性树（火/水/雷）各自的 `multiShot` 分支 `maxLevel:5`、每级 +1 发，且三树 `bulletCountBoost` 全局聚合（旧公式单树满级 +5）。出多重后清场过强。

### 改动（game - 副本.js）
- `multiShot.effect` 由 `m.bulletCountBoost += bl` 改为 `+= Math.floor(bl/2)`：Lv2+1、Lv3+1、Lv4+2、Lv5+2（满级+2/树，首发 Lv2 不浪费早期投入）。3 处（多重爆裂/多重电子/多重干冰）同改，desc 同步为"每2级额外+1发（满级共+2）"。
- 关键修正：`shootAttribute` 实际用 `attrModsForType(type)` 是**单树**修正，非三树叠加——多重是每棵树各自独立倍率（原分析"三树+15"有误，模拟器按单树建模是对的）。
- 副作用修复：原 `canSplit`（Lv5 命中分裂）靠 `bulletCountBoost>=5` 触发，floor 公式下单树最高+2 会静默废掉分裂。改为在 3 个 `recomputeXxxMods` 里 `if(bid==='multiShot' && bl>=5) m.canSplit=true`，`shootAttribute` 读 `m.canSplit`——与子弹数公式解耦，保住"多重 Lv5 质变=分裂"。

### 验证（scripts/sim_balance.js，默认 HP×1.5/EXP_BASE=3）
- 裸模拟（仅射击、无龙卷风/冰冻等）：old 单树Lv5=30/30 稳过 → floor 单树Lv5=0/30 但最低血1（贴边苦战）；双树Lv5 仍 30/30（重投值得赢）。
- 含义：单树多重不再"稳过"（真实游戏配合控场会稳过但有压力），直接命中用户"出多重就太易"的痛点。

## 修复微信开发者工具预编译 ENOENT「项目根目录/undefined」（顺手修的 bug）
- 报错：`SummerCompiler`/`PreCompileProject` 预编译阶段 `readFileSync('.../zombie-hunter-game/undefined')` ENOENT。
- 根因：微信开发者工具预编译会**静态扫描 `wx.createImage().src` 引用的资源文件**。当 `.src` 被赋值为无法静态解析的变量时，预编译器把路径算成 `undefined`。
  - 触发点：`loadWechatAvatarImage(url)` 的 `img.src = url`（`url` 是函数参数，远程头像 URL，编译期不可解析）；`loadOtherGameIcons` 的 `img.src = g.icon`（`g.icon` 是数组成员访问）。
  - 其余 `wx.createImage().src` 都是字面量且 `images/` 下文件真实存在（`qmxz_*`、`bdsjm_cat*`、`sqsdscj_money.png`），故不报错。
- 修复（`game - 副本.js`）：新增 `function createGameImage(){ const factory = wx.createImage; return factory(); }`，两处动态 `.src` 的图片改用 `createGameImage()`（间接调用规避静态扫描，行为不变）；`loadWechatAvatarImage` 加 `if(!url) return;` 守卫。已 `cp` 到 `game.js` 并 `node --check` 通过。
- 注：`OTHER_GAMES` 里 `beishumen` 的 `icon:''`（空串，运行时靠 `if(g.icon)` 跳过走 emoji）不是该报错源（空串会读成目录而非 /undefined）；保留。
- 若开发者工具仍报，可能是更激进的 AST 内联分析器；备选方案：关闭开发者工具「预编译」功能，或把动态 `.src` 改为字面量。

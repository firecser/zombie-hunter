## 关键技术约束（重要）
- 本项目是微信**小游戏**（game.js/game.json），而用户给的 `games/` 里三套都是 HTML5 网页游戏（index.html + js/css，非小游戏源码）。
- 小游戏无法内嵌/运行 HTML5 DOM 游戏，所以「打开其他游戏」只能走 `wx.navigateToMiniProgram` 跳到**已发布的小游戏 AppID**。
- 要让三款游戏真正可玩，需把它们转成小游戏并拿到 AppID，填入 `OTHER_GAMES[].appId` 即可，无需改其它代码。
- 选择页为全屏遮罩(0.85)，顶部标题 + 左上「‹ 返回」+ 3列卡片网格，布局由 `computeOtherGamesLayout()` 统一计算（绘制与点击共用，避免错位）。

## 2048 改为「游戏内直接可玩」（无需 AppID）
- 用户要求点击 2048 图标后直接玩，不要跳转。因此把经典 Cirulli 2048 算法**移植为 Canvas 实现**，在本小游戏内运行。
- 源码剖析：`games/2048/js/` 下 `grid.js`(4x4 矩阵/可用格/随机格)、`tile.js`(瓦片值+位置)、`game_manager.js`(核心 `move(dir)`，dir:0上1右2下3左)。actuator/keyboard 是 DOM 版，已弃用，改用 Canvas 绘制 + 滑动输入。
- 移植实现（game.js）：`g2048Init / g2048AddRandom / g2048Move / g2048MovesAvailable` 等，规则 100% 一致：每次有效移动后随机生成 2(90%)/4(10%)；合并每次移动每格仅一次；合成 2048 判定 won（可继续 keepPlaying）；无空格且无相邻相等则 over。
- 新增：`activeMiniGame` 状态机；`drawMiniGame2048()`（棋盘+分数/最高分本地持久化 `g2048Best` via wx.setStorageSync）；`handleMiniGame2048Input()`（滑动判定方向 + 点击「‹ 返回」「↻ 新游戏」、胜利后点击棋盘继续）。
- 入口：`OTHER_GAMES` 里 2048 项 `mode:'ingame'`，`handleOtherGamesClick` 据此调用 `startMiniGame()`；其余 `mode:'navigate'` 仍走 `openMiniGame()` 跳转。
- 验证：抽取引擎在 node 跑 12 条用例（横/纵、四方向、2048 胜利、死局），全部 PASS。
- 注：qmxzfzm(全民寻找房祖名)、bdsjm(暴打神经猫) 仍是 HTML5，暂无 AppID，点击仅 Toast；将来要内嵌需同样移植其逻辑。

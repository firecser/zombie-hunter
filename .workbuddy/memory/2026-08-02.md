## 关键技术约束（重要）
- 本项目是微信**小游戏**（game.js/game.json），而用户给的 `games/` 里三套都是 HTML5 网页游戏（index.html + js/css，非小游戏源码）。
- 小游戏无法内嵌/运行 HTML5 DOM 游戏，所以「打开其他游戏」只能走 `wx.navigateToMiniProgram` 跳到**已发布的小游戏 AppID**。

## 其他游戏选择页 UI 修复（关键 bug：改动"没生效"）
- 症状：遮罩改成不透明、返回按钮移右下角后，用户仍看到底部 Tab，且改动像没生效。
- 根因：`drawMainMenu()` 中 `drawOtherGamesPage()`（遮罩）在 3137 行，而 `drawMainMenuNav()`（底部导航栏）在 3142 行——**导航栏在遮罩之后绘制**，把不透明遮罩和右下角返回按钮都盖回去了，Tab 透出、返回按钮被压住。
- 修复：调换顺序——先 `drawMainMenuNav()`，最后再 `drawOtherGamesPage()`，使不透明遮罩成为最上层，完整覆盖主界面与底部 Tab；返回按钮画在遮罩上，清晰可点。
- 三重保险：① 绘制顺序遮罩在最后；② touchStart 内 `if (otherGamesModal.show) return;` 拦截所有主界面点击；③ touchEnd 内 `if (otherGamesModal.show){ handleOtherGamesClick(); return; }` 仅处理页内点击。
- 经验：在本项目 Canvas 框架里，模态/选择页等"覆盖层"必须在 `drawMainMenu()` 最末尾绘制，否则会被其后绘制的元素（尤其底部导航栏）盖住。

## 其他游戏页"按钮要按两次才生效"BUG 修复
- 症状：进入"其他游戏"页后，2048 卡片和返回按钮都要点两次才响应。
- 根因：`otherGamesJustOpened` 守卫误用。打开弹窗在 touchEnd 的 `handleMainMenuTouch()`(6745行) 里执行，但 touchEnd 顶部 6684 行的 `if (otherGamesModal.show)` 点击拦截块在那次手势发生时弹窗**尚未打开**，故打开手势本身没被吞；而 `handleMainMenuTouch` 设的 `otherGamesJustOpened=true` 留到了下一次触摸，把"第一次点卡片"给吞了 → 需点两次。
- 修复：彻底移除 `otherGamesJustOpened`（声明/设置/判断三处），touchEnd 拦截块改为 `if (otherGamesModal.show){ handleOtherGamesClick(); return; }`。已确认打开弹窗后 touchEnd 不再二次派发 click（6745 之后无 handleOtherGamesClick 调用），故去掉守卫不会造成"打开即误触"。现在单次点击即生效。
- 经验：本项目这种"打开即吞一次"的 justOpened 模式，只有当打开动作和点击处理在**同一个** touchEnd 分支内先后发生时才成立；若打开在分支之后（如 handleMainMenuTouch 在 6745），该标志只会误吞下一次点击，应改用别的方式或直接移除。

## Git 中文文件名 / 幽灵索引记录排查（补录未跟踪文档时）
- 现象：`git status --short` 把 `策划案/流量主与广告主关系说明.md` 列为未跟踪 `??`，但磁盘上 `策划案/` 实际只有 6 个文件（Python `os.listdir` 验证），该文件早已不存在；且 `git rm --cached` / `git add` 直接打中文路径报 "pathspec did not match"（Windows git 中文路径 NFC/NFD 码位差异导致命令行参数与索引内字节不匹配）。
- 权威判断：`git ls-files --others --exclude-standard` 才是"真正未跟踪"清单（不含索引残留）；`git ls-files --stage <dir>` 可查索引里残留的幽灵记录（文件在索引、磁盘已删）。
- 处理：用 `git add -A`（内部按索引/工作树比对，不依赖手打中文路径）自动纳入 12 个真实未跟踪文件，并把缺失的幽灵文件记为删除，干净解决。
- 经验：在本仓库处理中文名文件时，不要手打 `git add/rm <中文路径>`，优先用 `git add -A` 或 `git ls-files --others` 核对，避免路径编码坑。

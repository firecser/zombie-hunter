## 天赋 vs 局内三选一 关系梳理（用户提问后核查）
- 两套系统独立：**天赋 = 局外永久养成**（金币点，开局折入）；**三选一 = 局内升级面板**（`upgradePool` 9 项，`showUpgradePanel()` 随机取 3，`MAX_SKILLS=5`）。天赋本身不出现在三选一里。
- 共享底层字段（会叠加）：怪物之心/攻击力→player.damage；生命→maxHealth；攻速→fireRate；穿透→bulletPiercing；连射→bulletCount；护盾→skills.shield.level；爆炸→skills.explosive.level；闪电链→skills.lightning.level。
- 天赋独占（三选一没有）：暴击、冰冻、减速、炸弹上限、死亡射线、不朽之身、吞噬万物、金币获取、经验获取。
- 不朽之身实现：被动。`applyTalentsToBattle()` 置 `immortalCharges=等级`；仅在 `updateZombies()` 接触伤害致死时触发，扣 1 层、回 50% 血、紫色粒子、`immortalCooldownUntil=now+1500`。已确认全局唯一掉血点与唯一 gameOver 调用点都在此，覆盖完整。

### 已发现待修缺陷（未修，等用户决定）
1. **"1.5s 无敌"名不副实**：`immortalCooldownUntil` 只挡"再次复活"，期间照常掉血；若 1.5s 内血再归零会走 `else if → gameOver()`，剩余复活次数被浪费。应改为期间真免伤。
2. **MAX_SKILLS 槽位可被绕过**：天赋把 shield/explosive/lightning 的 level 抬到 >0 后，`applyUpgrade()` 的 `if (skills[type].level === 0)` 不成立 → 局内再选这三个不会写入 `acquiredSkills`，等于不占 5 个槽位。
3. 战斗 UI 未显示剩余复活次数。

## v1.0.56 + 跳级三选一覆盖 Bug 修复（本地未提交）
- 现象：炸弹清屏加经验后若「跳级」（跨多级），会连出两次三选一，第二次把第一次的 `upgradeOptions` 覆盖，玩家丢失第一次选择；且跨多级只弹一次面板。
- 根因：`levelUp()` 直接 `showUpgradePanel()` 无守卫；`useBomb` 仅 `setTimeout(levelUp,1000)` 调一次，跨多级不补弹，且延迟回调可能在已有面板时覆盖。
- 修复（game - 副本.js）：
  1. `levelUp()` 顶部加守卫：面板已显示(`gameState==='upgrade'`)直接 return，不覆盖；并加 `player.exp < player.expToLevel` 校验，防炸弹延迟回调在经验已消耗后误升。
  2. `applyUpgrade()` 选完一级后连锁检查 `player.exp >= player.expToLevel` 再 `levelUp()`，使跳级逐级都能选。
- 验证：独立状态机模拟（T1 跨级弹2面板均能选 / T2 先有面板时延迟回调不覆盖且连锁补出第2个 / T3 经验不足无误升）全部通过；`node --check` 双文件通过。

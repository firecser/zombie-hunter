### ENOENT undefined 报错根因（重要，已根治）
- 现象：`[] ENOENT: no such file or directory, open '.../zombie-hunter-game/undefined'`，栈 `PreCompileProject.getFile → SummerCompiler.getFile → FileUtils.getFile → readFileSync`。路径 `root/undefined` 来自 `path.join(root, undefined)`（论坛同款报错是 `root/[object Object]` = `path.join(root, {})`，同源）。
- 第一轮误诊：`uploadWithSourceMap:false + 删 game.js.map` 未解决，报错复现。
- 第二轮（部分有效）：`useCompilerModule: false` 回退旧编译器——**只对 IDE 启动全新编译有效，对文件变化触发的增量重编译复现**（所以用户重启后没报、git push 触发 DevTools 后台重编译又报）。已提交 v1.0.59 推送。
- 真因（最终定位）：根目录下嵌套的废弃 `zombie-hunter-game/`（Apr16 旧快照）含**第二个 project.config.json**，DevTools 预编译把它当「子项目」递归预编译，某相对路径字段解析成 undefined → `root/undefined`。`git push` 不改本地文件，但触发 DevTools watch `.git` 变化 → 增量重编译 → 撞上该路径。
- 根治：本地提交 `bf3dc67` 清理 Apr16 废弃快照（zombie-hunter-game/ 含第二 project.config.json、zombie-hunter-game.zip、zombie-hunter-levels/、根 README.md/SETUP.md 共 8 文件），工作区已 GONE。运行时文件（game.js/game.json/project.config.json/images 等）完好。
- 验证：请用户**彻底重启微信开发者工具**（关掉再开）再编译/上传，确认 undefined 报错彻底消失。
- 教训：① git push 不会改本地文件，不能甩锅给 push；② 改配置只对某条编译路径有效时要继续挖根因（异常目录结构）；③ 一个项目根出现第二个 project.config.json 会让 DevTools 预编译递归出错。

### ⚠️ 最终权威结论（更正前面的误诊）
- 前面「真因=嵌套第二 project.config.json / useCompilerModule:false / 关 sourceMap」**全部是误诊**。这些是巧合性"没报"，不是根因。
- **真正根因：微信开发者工具 Stable `2.01.2510290`（同系列 2.01.25xxx）自身的已知 bug**，与项目代码/配置/目录结构**完全无关**。
- 证据：开发者社区官方同款帖子（栈帧 `af7e7c98cbc5339efce1d7549388ba10.js:2:676` 逐字相同），报同样错的用户的版本 `2.01.2510280`（同系列），也是"纯 Canvas/H5、无引擎"。官方 AI 答复：下载最新**开发版(nightly)** 验证；该用户实测"换 nightly 后就没有这个错误了"。
- 报错机制：DevTools 文件监听 → 增量重编译走 `PreCompileProject → SummerCompiler.getFile(undefined)`，属偶发 race（所以有时不报、有时报），`useCompilerModule:false` 只关"主编译"、关不掉"预编译阶段的 SummerCompiler"，故无效。
- **唯一确认有效的解决：升级微信开发者工具到最新 nightly（或更新后的 Stable）**。升级前不要再用 git push 当"是否报错"的测试——它必然触发重编译、且只是偶发，不具判定意义。
- 缓解（不保证根除）：DevTools 内关闭"编辑时自动编译"，减少增量重编译触发频率。

## 修复：看广告后背景音乐消失
- 原因：BGM 用 `wx.createWebAudioContext()`；微信播放激励视频会把 AudioContext 挂起（suspended），广告关闭后 context 不自动恢复，导致音乐永久静音。
- 修复：`showRewardedAd` 的 `resume()` 回调里，广告结束后调用 `AudioSystem.resume()`，并在 `gameRunning && musicEnabled && ctx.state==='running'` 时 `AudioSystem.startBGM()` 重启 BGM（startBGM 内部先 stop 旧的再起新的）。
- 验证：无头测试 5 项全过（模拟 context 被挂起 → 广告结束恢复 running + BGM 重启；音乐关闭时只恢复 context 不重启 BGM）。双文件 node --check OK。

## 修复：看广告后过一会游戏卡死（drawMine 颜色拼错）
- 现象：3 次广告看完过一会，游戏帧崩溃卡死。报错 `addColorStop ... 'rgba(255,0.95)' could not be parsed`，来自 `drawMine`（game.js:2238）。
- 根因：`drawMine` 发光核心颜色基串 `coreBase = armed ? 'rgba(255,' : 'rgba(120,175,255,'`，armed 分支漏了 G/B 通道；拼出 `${coreBase}0.95)` = `rgba(255,0.95)` 非法，CanvasGradient.addColorStop 抛异常打断 gameLoop → 卡死。触发时机：地雷布署且 `now >= m.armTime`（armed=true）后才走该分支，所以"布雷→看完广告→雷激活"瞬间才崩。
- 修复：`coreBase` armed 分支改为 `'rgba(255,90,60,'`（红心），armed 时拼出 `rgba(255,90,60,0.95)` 合法。副本与 game.js 同步，node --check 双文件 OK。
- 附带说明：日志里的 `insertTextView/updateTextView ... 33642 not found` 是激励视频广告原生组件（关闭按钮等）的清理告警，来自微信广告 SDK 而非 canvas 代码，非致命、不影响游戏主循环，无需改动。

## 热能爆炸范围惩罚"没生效"根因与修复（v1.0.85 待提交，接上）
- 现象：选 热能爆炸 后爆炸特效半径没变小。
- 根因：每次选爆炸弹卡（基础或分支）都会 skills.explosive.level++，基础半径 (40+level*20) 每级+20；原 热能爆炸 用乘性 -10%/级(explRadiusMul)，被等级增长完全抵消——选第1级时半径反而变大(108>100)。
- 修复：热能爆炸范围改为平减像素 explRadiusCut += 40*bl（每级-40，超过基础每级+20），结算公式 explosionRadius = max(35, (40+level*20) - explRadiusCut)。这样每次选卡半径净减20px/级，取舍肉眼可见；bl5 同等级半径缩至 ~18%。
- 同步：_expl_test.js(thermalExplode 改验 explRadiusCut===200)、_expl_balance.js 重写(平减模型+同等级半径对比)；双文件 node --check + _expl_test(31项)/_fh_test 全过。

## 修复：updateBullets 崩溃 Cannot read property 'x' of undefined（v1.0.85+ 待提交）
- 现象：微信真机 game.js:4209（updateBullets）`Cannot read property 'x' of undefined`，闪电/爆炸同时击杀多只僵尸时必现。
- 根因：`damageZombie` 在僵尸死亡时**立即把其从 `zombies` 数组 splice 移除**（3722-3723）。而多处 `for (const z of zombies)` 升序遍历中调用 `damageZombie`，一旦在**当前迭代索引之前**的位置删除了元素，for...of 迭代器下一步会读到 `undefined`，于是 `Math.hypot(... z.x ...)` 读 `.x` 抛错。典型「遍历中 mutate 数组」bug。Phase 2 后火树增伤/引燃让单发爆炸更易秒杀多只僵尸，触发频率升高才暴露。
- 修复：把调用 `damageZombie` 的所有 `for (const z of zombies)` 升序循环改为**倒序索引遍历** `for (let k = zombies.length-1; k>=0; k--)`，splice 当前元素不影响未遍历部分。涉及：
  - updateBullets：爆炸 AOE 循环、穿透溅射(pierceSplash)、暴击小爆炸(critExplode)
  - updateFields：地雷爆炸、龙卷风风系 DPS（_wind）
  - update（死亡射线天赋）：`for (const z of zombies) damageZombie`
  - （灼烧 DOT 循环 3966、闪电链 superConduct 内圈、组合技 fx 单目标 此前已安全/只读，未改）
  - 顺手修焚身：爆炸 AOE 内对同目标二次 `damageZombie` 加 `z.health > 0` 守卫，避免对已死目标重复击杀/掉落计数。
- 验证：新增 `_updatebullets_crash_test.js`（构造爆炸弹一发秒杀 5 只聚集僵尸场景，断言无抛异常且 5 只全清）；_expl_test(36项)/_fh_test 回归通过；双文件 cp 同步 + node --check OK。
- 教训：凡在遍历 zombie/bullet 数组过程中可能 mutate（splice/删除）该数组的代码，必须用倒序索引或快照副本，绝不能升序 for...of。

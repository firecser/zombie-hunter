## 修复：看广告后背景音乐消失
- 原因：BGM 用 `wx.createWebAudioContext()`；微信播放激励视频会把 AudioContext 挂起（suspended），广告关闭后 context 不自动恢复，导致音乐永久静音。
- 修复：`showRewardedAd` 的 `resume()` 回调里，广告结束后调用 `AudioSystem.resume()`，并在 `gameRunning && musicEnabled && ctx.state==='running'` 时 `AudioSystem.startBGM()` 重启 BGM（startBGM 内部先 stop 旧的再起新的）。
- 验证：无头测试 5 项全过（模拟 context 被挂起 → 广告结束恢复 running + BGM 重启；音乐关闭时只恢复 context 不重启 BGM）。双文件 node --check OK。

## 修复：看广告后过一会游戏卡死（drawMine 颜色拼错）
- 现象：3 次广告看完过一会，游戏帧崩溃卡死。报错 `addColorStop ... 'rgba(255,0.95)' could not be parsed`，来自 `drawMine`（game.js:2238）。
- 根因：`drawMine` 发光核心颜色基串 `coreBase = armed ? 'rgba(255,' : 'rgba(120,175,255,'`，armed 分支漏了 G/B 通道；拼出 `${coreBase}0.95)` = `rgba(255,0.95)` 非法，CanvasGradient.addColorStop 抛异常打断 gameLoop → 卡死。触发时机：地雷布署且 `now >= m.armTime`（armed=true）后才走该分支，所以"布雷→看完广告→雷激活"瞬间才崩。
- 修复：`coreBase` armed 分支改为 `'rgba(255,90,60,'`（红心），armed 时拼出 `rgba(255,90,60,0.95)` 合法。副本与 game.js 同步，node --check 双文件 OK。
- 附带说明：日志里的 `insertTextView/updateTextView ... 33642 not found` 是激励视频广告原生组件（关闭按钮等）的清理告警，来自微信广告 SDK 而非 canvas 代码，非致命、不影响游戏主循环，无需改动。

- 用户质疑：感觉 -3% 才对。复核发现：`fireMul` 乘的是**射击间隔**，<1=间隔短=射速高。`1/1.03` 实际给 +3% 射速，**符号写反**；而平衡脚本原注释"微射速代价"表明设计本意是 -3% 惩罚。我上一步"改文案+3%"只是迁就了写反的代码，没动根因。
- 正确修复（用户选推荐方案）：翻转代码符号 + 补偿伤害，使 -3% 惩罚下仍平衡。
  - 代码：`m.dmgMul *= Math.pow(1.15,bl)` → `Math.pow(1.20,bl)`；`m.fireMul *= Math.pow(1/1.03,bl)` → `Math.pow(1.03,bl)`（真 -3%/级 间隔变长）。

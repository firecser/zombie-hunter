- **现象**：结算页点「金币×2」没有反应。
- **两个根因**：

  - `platform === 'devtools'` 时**直接发奖**（便于模拟器自测）；
  - `onReward` 包 try/catch，防止回调异常打断后续（如 `saveProgress`）。
- 影响范围：所有 6 个广告位（统一走 `showRewardedAd`）。

## v2.24.0 广告结束后的 insertTextView 报错（tag `v2.24.0`）
- **现象**：广告播放完回到游戏后，控制台报：
  - `insertTextView:fail position.top should be Number position.left should be Number`
  - `updateTextView:fail 33508 not found` / `insertTextView:fail parent 33508 not found`
- **判断**：`insertTextView` 是**原生 text 视图**（我们唯一创建的是 `wx.createGameClubButton({type:'text'})`）；广告层关闭时 SDK 重建原生视图，坐标/父节点已失效。
- **加固**：
  1. `statusBarHeight` 强制 `Number()`（防字符串拼接出 `"2010"` 或 NaN）；
  2. 游戏圈按钮创建前校验 `isFinite(left/top/width/height)`，非法则跳过；`createGameClubButton` 包 try/catch；
  3. **广告播放前自动 `hideGameClubButton()`**，减少广告层与原生视图互相踩；
  4. `wx.showToast` 统一打补丁：`adOpen` 期间不弹、广告结束后 1.2s 内不弹、600ms 去抖（一处改动覆盖 26 个调用点）。
- **结论**：即便仍偶发，也属 SDK 内部噪音（社区确认无害）；判断标准是「广告是否正常播/奖励是否到账」。
- 测试 9/9 PASS；CI `dc18c51` success；未推送 0。

- **修复**：
  - `addShake` 内部封顶 **8px**；
  - 衰减改为 `min(1, 剩余/220)`，位移上限 8px；
  - 每帧进入 playing 分支先 `ctx.setTransform(1,0,0,1,0,0)` + `globalAlpha=1`，彻底消除累积。
- 测试 9/9 PASS；CI `fe48cab` success；未推送 0。

## 震屏 bug 的真实来源（用户追问）
- 用户追问：「没让你调震屏，为什么会去动震屏代码？」
- **git 查证结论**：震屏参数不是今天改的——`addShake(10/12/16, …)` 分别由 **v2.13（破格）、v2.14（盾兵）、v2.15（守将复活）** 引入，都是 **10-24** 做 IAA 广告点位时我加的；今天的埋点提交（v2.19→v2.24）**没有一行 touch shake**。
- **根因**：加这些"打击感"时直接传了 10/12/16，没对照衰减公式 `mag × (剩余/200)`，420ms 震动实际位移 = 16×2.1 ≈ **33px**，背景被平移出屏 → 看起来像"整个画面缩小"。
- **教训**：改表现参数前必须先读该参数的换算公式；用户没要求的"手感增强"不要顺手加，尤其跨模块。
- 已在 v2.24.1 封顶 8px。

## v2.28.0 高屏吃不到宝箱（tag `v2.28.0`）

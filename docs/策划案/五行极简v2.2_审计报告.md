## 二、发现的问题

### 🔴 BUG-A（严重·经济断裂）→ **已修复（见 §4.1）**：击杀金币被 P6 砍掉 98%

P6 为压时长把怪量从 **1,663 只**降到 **159 只**，但**每只怪的金币没跟着调**：

| 项 | 旧曲线 | 新曲线 |
|---|---|---|
| 单关击杀金币 | **≈69,944** | **≈1,269**（−98%） |
| 单关通关奖励 | 200 ~ 1,970 | 不变 |
| 60 关累计收入 | ≈420 万 | **≈13.8 万** |
| 新树全满所需 | — | **≈181 万** |

→ **一辈子只能点满约 7.6% 的天赋树**，养成循环实质断裂。

同时说明：旧版「击杀金币 7 万/关 vs 通关奖励 2 千」其实也违背了定稿「直线型通关奖励为主导」的设计意图，只是旧消耗曲线同样巨大，双方凑合能转。

**三个修法（待你选）：**

| 方案 | 做法 | 结果 |
|---|---|---|
| **A（推荐）** | 击杀金币 **×20**（normal 40 / tank 100 / giant 200 / boss 600） | 单关 ≈2.5 万、60 关 ≈150 万 ≈ 满树的 83%，需重复刷少量关卡 |
| B | 天赋消耗 **÷10**（300→30、800→80、1600→160…） | 满树 18 万，与当前 13.8 万收入匹配，但消耗曲线整体变小、后期"2 次幂"的陡峭感减弱 |
| C | 通关奖励斜率 30→**300** | 单关最高 1.8 万、60 关 ≈54 万，仍需配合提高击杀金币 |

### 🟠 BUG-B（失效子系统）→ **已删除（见 §4.2）**：`getDmgCouple` 仍按旧 1.6 曲线，恒等于 1

`getDmgCouple(idx, progress)` 用 `expectedIdx = 1.6^progress` 做基准；P6 把波次曲线改成 1.25 后，
再叠加 v2.2 的 `getPlayerDpsIndex()` 恒≈1，`ratio` 永远 <1 → **`couple` 恒为 1**，整套「难度-火力耦合」实质失效。

- 不崩、不产生 NaN（有 `Math.max(1, …)` 兜底）。
- 但它现在是**死系统**：要么按 1.25 重写基准、要么整体删掉（归入后续清理）。

### 4.2 删除失效耦合（BUG-B → 方案 ②）

删除 `getPlayerDpsIndex()` / `getPickProgress()` / `getDmgCouple()` 三个函数，`updatePendingSpawns` 的血量改为：

```js
const healthMult = stage.healthMult;   // 只由关卡基线 × 波次表决定
```

同时删掉 `updatePendingSpawns` 里那段基于 1.6 阶梯的过期注释。

### 4.3 补相生引导（P5.3）

- 第 13 关起、本局首次触发相生连携时，`synergyHintUntil = now + 4000`
- `drawUI` 在坞上方绘制横幅：**「相生连携：水 生 木 · 伤害 +20%」**
- 每局一次（`synergyHintDone`），避免刷屏

### 4.4 🔴 额外发现并修复：局内增益跨局残留（BUG-D）

P3 的三选一增益（`restraintMult` / `synergyDurBonus` / `synergyDmgBonus` / `autoDpsBonus`）**只在开局初始化一次、从未重置**——
上一局把克制堆到 3.5，下一局开局仍是 3.5。与 P4 修过的 `elementLevels` 是同一类 bug。

已在 `startGame` 统一归零，并把连携态（`synergyUntil` / `lastActiveElement` / 引导标记）一并重置。
`smoke_p4.js` 增加源码级断言，防止以后被删回去。

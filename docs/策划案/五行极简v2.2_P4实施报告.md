## 二、结算层（`applyTalentsToBattle`）

只产出 6 个量，全部写入既有的 `talentMods` / 新增全局：

| 输出 | 用途 |
|---|---|
| `elemAtkFlat[el]` | 进 `shootElement` 单发分子 |
| `talentMods.healthBonus` | 进 `player.maxHealth` |
| `wallDefPct` | 城墙受击 `damage *= (1 - wallDefPct)` |
| `talentMods.critChance` | `getCritChance()` |
| `talentMods.critDamageMult` | `getCritMult()`，基准 **1.5×** |
| `elementBaseLevels[el]` | 本局起始 `elementLevels` |

其余旧字段（`damageBonus` / `fireRateBonus` / `piercingBonus` / `bulletCountBonus` / 技能等级 / `goldMult` / `expMult` / `deathray` / `immortal` / `lifesteal`）**全部固定为中性值**，不再有天赋予点可影响。

## 三、顺手修掉一个 P3 遗留 bug

**`elementLevels` 跨局残留**：P3 的局内精通只增不减，而 `startGame` 从未重置它 —— 上一局把火升到 10，下一局开局仍是 10。

P4 在 `startGame` 中加入：

```js
for (const el of ['金','木','水','火','土']) {
    elementLevels[el] = Math.min(ELEM_MASTERY_MAX, 1 + (elementBaseLevels[el] || 0));
}
```

每局都从「1 + 局外精通」起算，局内成长只在本局有效。

## 六、需要你决策的一点：旧存档的天赋投资

存档仍按 `talentLevels[节点id]` 存储。旧 id（`core`/`damage`/`crit`/…）在新树里不存在，读取时会**静默归零**——即老玩家的天赋投资会清零（金币不返还）。

三种处理方式，等你选：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（当前）** | 不处理，旧投资清零 | 老玩家体验受损，但实现最干净 |
| B | 按旧总等级折算为新树节点等级（如每 10 级旧天赋 → 1 级新节点） | 需写迁移函数，一次性的 |
| C | 全额返还金币（按旧节点累计花费估算） | 数值可能膨胀，需封顶 |

# 排行榜清查报告

| 项 | 结论 |
|---|---|
| 清查时间 | 2026-10-25 |
| 结论 | **排行榜是假的**——纯 UI + 硬编码假数据，没有任何真实成绩 |
| 影响 | 留存/k 值为 0；存在"欺骗感"风险 |

---

## 一、现状（逐项核实）

| 检查项 | 实际情况 | 证据位置 |
|---|---|---|
| 全服榜数据 | **24 条硬编码**（冰霜之王/雪域狂魔…地区+战力全是编的） | `rankCityData` |
| 好友榜数据 | **4 条硬编码**（小明/老王/小李/阿强） | `rankFriendData` |
| 开放数据域 | **未配置**（`game.json` 无 `openDataContext`，`js/` 为空） | `game.json` |
| 成绩上传 | **0 处** `wx.setUserCloudStorage` | 全文搜索 |
| 好友数据拉取 | **0 处** `wx.getFriendCloudStorage` | 全文搜索 |
| 玩家名次 | `getPlayerRank()` 拿**本地战力**去和**假数据**比 | `getPlayerRank` |

### 具体表现

1. 全服榜：把玩家自己按战力插进 24 个假人里，所以"第 13 名"这类名次是**对假数据算出来的**。
2. 好友榜：永远显示"小明/老王/小李/阿强"，无论玩家有没有好友。
3. 成绩不上传 → 换手机、清缓存后记录消失。

---

## 二、风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| **欺骗感** | 高 | 玩家只要有 1 个好友在玩，就会发现榜上没有他 |
| 无法产生社交动机 | 高 | 假榜不会让人想"超过他"，k 值贡献为 0 |
| 数据不可迁移 | 中 | 换设备即丢 |
| 审核风险 | 中 | 展示虚构用户数据，可能被判"虚假内容" |

> **建议：立刻下线假数据，不要保留"看起来像真的"的假榜。**

---

## 三、正确做法（微信合规路径）

### 3.1 好友榜：开放数据域（唯一合规方式）

```
主域 game.js  ──postMessage──▶  子域 openDataContext/index.js
      │                                   │
      │                          wx.getFriendCloudStorage
      │◀────── sharedCanvas ─────────────┘
   绘制到主画布
```

**为什么必须走子域**：好友数据属于隐私数据，微信禁止主域直接读取，只能在开放数据域内使用并渲染成一张图。

### 3.2 成绩写入

```js
wx.setUserCloudStorage({
  KVDataList: [{ key: 'best', value: JSON.stringify({ lv, wave, kills, ts }) }]
});
```

写入时机：通关、失败、每日挑战结束。**只在成绩变好时写**，减少调用。

### 3.3 全服榜：没有服务端就不要做

真实全服榜需要后端（云开发或自建）。当前项目**没有后端**，所以：

| 方案 | 结论 |
|---|---|
| 假数据 | ❌ 立即删除 |
| 云开发数据库 | 可做，但引入后端成本与合规（用户数据出境/存储） |
| **改「我的战绩」** | ✅ **推荐**——本地历史最佳 + 本周最佳 + 总击杀，真实、零成本 |

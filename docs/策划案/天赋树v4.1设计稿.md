## 一、设计目标与定位

| 维度 | 结论 |
|---|---|
| 体系 | **物理 + 五行**（金木水火土）双轴养成 |
| 主数值类型 | **绝对数值为主**（±伤害/墙血/护甲/金币），百分比仅限「暴击率」「暴击倍率」两类安全项 |
| 对局影响 | 全部效果**对局内正向**（开局快照式聚合进 `talentCombat`，不改战场机制） |
| 成长长度 | 满级约 74 节点、单元素深投 + 防御构成长线；战斗力满级 ≈ **1870** |
| 保留项 | 「升级天赋 → 增加玩家战斗力」规则（`calculatePower = Σ level × perLevelPower`）原样保留 |
| 解锁门槛 | 通过 `prerequisite` 前置树逐步开放高层节点与技能卡 Lv3–Lv5；**Tier 升级做「质变」**：Lv3→Lv4→Lv5 之间须把基础节点逐级推满——五行系(强击/锐目/致命/相生) v4.2 redesign，防御系(护甲/城血/修复/格挡/反伤) v4.3 redesign，详见 §四/§六 |

**设计红线（护栏）**
1. 作用域收窄为【攻 / 防 / 血 / 暴击 / 解锁】五类，不触碰范围、技能 CD、控制时长。
2. 全局乘总伤 = **禁止**（红区）。
3. 系数增量（`coeff`）仅限元素深节点，且**线性累加、封顶有限**。
4. 范围 / 节奏(CD) / 控制时长类天赋 = **不投放**。

## 二、五行映射（代码实装，已核对）

相生 `WX_GEN = {火:"土", 土:"金", 金:"水", 水:"木", 木:"火"}`；相克 `火→金→木→土→水→火`。

| 元素 | 强击系数键 | 克制目标（锐目·克制 / 致命·克制 生效对象） | 相生搭档（相生共鸣受益者） |
|---|---|---|---|
| 火 | `coeff_火` | 金 | 土 |
| 金 | `coeff_金` | 木 | 水 |
| 木 | `coeff_木` | 土 | 火 |
| 土 | `coeff_土` | 水 | 金 |
| 水 | `coeff_水` | 火 | 木 |

> `getElementBonus` 中以 `j = WUXING_ELEMENT[目标元素]` 取键，故 `critChanceVsCounter_火` 仅在「目标为金（火克金）」时触发。
> `coeffGen_火` 的 `partner = WX_GEN["火"] = "土"`，即给**土**元素系数加成。

## 三、系统总览

- **结构**：7 大族 —— 根脉(6) + 五行系(5×7=35) + 防御(12) + 统御(21) = **74 节点**（id `0`–`73`）。防御(12) = 基础 5（41–45）+ 进阶 4（46–49）+ Tier 门 3（71–73）。
- **生效模型**：`applyTalentsToBattle()` 在开局把每个节点 `level` 聚合成 `talentCombat` / `talentMods` 快照；对局内**不再重算**（快照式）。
- **节点字段**（代码键 → 语义）：
  `level`(当前级) · `max`(上限) · `cost`(每级金币) · `name`(显示名) · `icon`(图标键) · `effect`(效果类别键) · `perLevelPower`(战斗力权重) · `prerequisite`(解锁门 `{前置id: 所需级}`，空对象=无门槛)。
- **战斗力**：`calculatePower = Σ node.level × node.perLevelPower`（保留项）。

| `syn_crit` | `talentMods[critKey]/[critMultKey]` | `+0.15·lv` / `+0.5·lv` | |
| `syn_all` | atkMul/armor/hpAdd/critKey/critMultKey | `×(1+0.20)` / `+0.15` / `+200` / `+0.20` / `+0.8` | 终极大包 |

**攻击乘区示例（火系全套）**：`atkMul = (1+0.04×5) × (1+0.15×1) × (1+0.20×1) = 1.20 × 1.15 × 1.20 ≈ 1.656`（+65.6% 攻击）。

## 七、战斗力规则与满级上限

- **规则**：`calculatePower = Σ (node.level × node.perLevelPower)`，与战斗数值解耦，仅作成长反馈与排行。
- **满级总战斗力**：
  - 根脉 6×5×2 = 60
  - 五行 5 系 × (强击50 + 锐目50 + 致命50 + 相生50 + 解锁3×10) = 5 × 230 = 1150
  - 防御 基础5×10×4 + 进阶4×10×4 + 门3×1×10 = 200 + 160 + 30 = 390
  - 统御 20×1×12 + 1×1×30 = 270
  - **合计 ≈ 1870**

## 八、UI 与交互（已实现）

- **布局 v4.4（竖版 KOA 风格）**：`drawMainMenuTalent` 改为 **4 列垂直科技树 + 纵向滚动**——列 0 根脉、列 1 五行系(火/金/木/土/水)、列 2 防御、列 3 统御；每列节点按依赖深度从上到下排列。顶部保留「天赋总览」+ 实时 `calculatePower()` + 滚动提示，右侧滚动条。
- **连线（核心）**：先绘制前置连线后绘制节点。每个 `prerequisite` 从父节点底部向子节点顶部拉一条圆角斜线；子节点未解锁时连线灰化/半透明，已解锁时取父节点图标色，MAX 节点末端带金色/色光晕，形成清晰的科技树脉络。
- **命中框**：每帧按滚动偏移注册全部 74 个命中框（`hb` 用与 `handleTalentClick` 一致的 `lM` 键：`x`/`y`/`size`/`id`），点击命中即弹升级弹窗。
- **锁定态**：`locked = !isTalentUnlocked(id)`；锁定时灰化填充/描边并绘制「锁」字，前置树可见。
- **升级流程**：`handleTalentClick → showTalentModal(id) → drawTalentModal` 按 `level/max/cost` 升级，扣 `gold(lM[2][9])`；升级后**下一战** `applyTalentsToBattle` 重算快照（`calculatePower` 实时变）。

## 九、生效时机与存档

- `applyTalentsToBattle()` 在 `startGame` 时调用，重建 `talentCombat` / `talentMods` 快照；对局内读取快照，不重算。
- `loadPlayerData` 按节点 id 合并存档；新 id 无存档则跳过，向后兼容。
- `isTalentUnlocked(id)`：空 `prerequisite` 或缺前置节点 → 解锁；任一前置等级不足 → 锁定（已修复崩溃 bug，见 §十一）。

## 十、与五行属性技能的关系

- 本天赋树的 `coeff_*` / `critChanceVsCounter_*` / `critMultVsCounter_*` / `coeffGen_*` 直接挂钩 `getElementBonus` 的五行伤害结算，是「属性技能」的养成放大器（详见 `docs/策划案/五行属性技能设计.md`）。
- `unlock_×_3/4/5` 控制对应元素技能卡的 Lv3–Lv5 是否进入三选一池，是天赋 → 技能的解锁闸门。

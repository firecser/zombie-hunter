## 一、设计目标与定位

| 维度 | 结论 |
|---|---|
| 体系 | **物理 + 五行**（金木水火土）双轴养成 |
| 主数值类型 | **绝对数值为主**（±伤害/墙血/护甲/金币），百分比仅限「暴击率」「暴击倍率」两类安全项 |
| 对局影响 | 全部效果**对局内正向**（开局快照式聚合进 `talentCombat`，不改战场机制） |
| 成长长度 | 满级 **119 节点**、五行系每元素拉成 **三阶段 I/II/III 深养成链**（核心→攻/防/血/暴 I→门Lv3→II→门Lv4→III→门Lv5），单元素深投 + 防御 + 统御构成长线；战斗力满级 ≈ **2320** |
| 保留项 | 「升级天赋 → 增加玩家战斗力」规则（`calculatePower = Σ level × pwr`）原样保留 |
| 解锁门槛 | 通过 `prerequisite` 前置树逐步开放高层节点与技能卡 Lv3–Lv5；**Tier 升级做「质变」**：每个元素把攻/防/血/暴 各拆成 I/II/III 三阶段，相邻阶段之间须用 `解锁Lv3 / 解锁Lv4 / 解锁Lv5` 三道门隔开——门要求「上一阶段四个节点全部 ≥Lv3」才能买下一道门，从而把一条属性养成链从原 1 段拉长成 3 段、大幅延长养成深度。防御系（v4.3 起）、统御系同理遵从门控逻辑。 |

**设计红线（护栏）**
1. 作用域收窄为【攻 / 防 / 血 / 暴击 / 解锁】五类，不触碰范围、技能 CD、控制时长。
2. 全局乘总伤 = **禁止**（红区）。
3. 系数增量（`coeff`）仅限元素深节点，且**线性累加、封顶有限**（每元素核心+攻I+攻II+攻III 共 4 节点累加，封顶 +1.25）。
4. 范围 / 节奏(CD) / 控制时长类天赋 = **不投放**。

## 二、五行映射（代码实装，已核对）

相生 `WX_GEN = {火:"土", 土:"金", 金:"水", 水:"木", 木:"火"}`；相克 `火→金→木→土→水→火`。

| 元素 | 强击系数键 | 克制目标（锐目·克制 / 致命·克制 生效对象） | 相生搭档（相生共鸣受益者） |
|---|---|---|---|
| 火 | `coeff_火` | 金 | 土 |
| 金 | `coeff_金` | 木 | 水 |
| 木 | `coeff_木` | 土 | 火 |
| 土 | `coeff_土` | 水 | 金 |
| 水 | `coeff_水` | 火 | 木 |

> `getElementBonus` 中以 `j = WUXING_ELEMENT[目标元素]` 取键，故 `critChanceVsCounter_火` 仅在「目标为金（火克金）」时触发。
> `coeffGen_火` 的 `partner = WX_GEN["火"] = "土"`，即给**土**元素系数加成。

> **v4.9 说明**：五行系在 v4.9 不再使用「锐目·克制 / 致命·克制 / 相生共鸣」三类节点，改为**攻 / 防 / 血 / 暴 四轨道 × I/II/III 三阶段**的纯养成链（见 §四 4.2）。克制暴击（`critChanceVsCounter_*` / `critMultVsCounter_*`）与相生（`coeffGen_*`）效果键在 v4.9 天赋树中**不再出现**（保留在 §五 公式表仅作历史兼容说明，当前 `talentData` 未引用）。

## 三、系统总览

- **结构**：4 大族 —— 根脉(6) + 五行系(5×16=80) + 防御(12) + 统御(21) = **119 节点**（id `0`–`118`）。
  - 五行系 80 = 5 元素 × 16 节点（核心 1 + 攻/防/血/暴 I/II/III 各 1 = 12 阶段节点 + 解锁Lv3/4/5 三道门 = 3）。
  - 防御 12 = 基础 I 5（86–90）+ 解锁Lv3 门（91）+ 进阶 II 2（92–93）+ 解锁Lv4 门（94）+ 进阶 III 1（95）+ 解锁Lv5 门（96）+ 顶石协同壁垒（97）。
  - 统御 21 = 火系 4 根（攻/防/血/暴·火 = 98–101）+ 金木土水各 4（102–117）+ 全系通晓（118）。
- **生效模型**：`applyTalentsToBattle()` 在开局把每个节点 `level` 聚合成 `talentCombat` / `talentMods` 快照；对局内**不再重算**（快照式）。
- **节点字段**（代码键 → 语义）：
  `level`(当前级) · `max`(上限) · `cost`(每级金币) · `name`(显示名) · `icon`(图标键) · `effect`(效果类别键) · `pwr`(战斗力权重) · `prerequisite`(解锁门 `{前置id: 所需级}`，空对象=无门槛)。
- **战斗力**：`calculatePower = Σ node.level × node.pwr`（保留项）。

## 五、数值公式表（applyTalentsToBattle 路由，已逐条核对代码）

## 七、战斗力规则与满级上限

- **规则**：`calculatePower = Σ (node.level × node.pwr)`，与战斗数值解耦，仅作成长反馈与排行。
- **满级总战斗力**：
  - 根脉 6×5×2 = 60
  - 五行 5 系 ×（核心 10×5 + 攻/防/血/暴 各轨道 I+II+III=3×5×4=60 ×4 轨道 + 解锁Lv3/4/5 各 1×10=30）
    = 5 × (50 + 240 + 30) = 5 × 320 = **1600**
  - 防御 基础 I 5×10×4 + 门3 1×10 + 进阶 II 2×10×4 + 门4 1×10 + 进阶 III 1×10×4 + 门5 1×10 + 顶石 1×10×4
    = 200 + 10 + 80 + 10 + 40 + 10 + 40 = **390**
  - 统御 火 4×1×12 + 金木土水（攻/防/血/暴 各 4×1×12 = 48×4 = 192）+ 全系通晓 1×1×30
    = 48 + 192 + 30 = **270**
  - **合计 ≈ 60 + 1600 + 390 + 270 = 2320**

> 五行系战斗力由 v4.8 的 1150 提升至 1600，主因是把每元素 4 个养成节点（强击/锐目/致命/相生）扩成 12 个阶段节点（核心+攻/防/血/暴 × I/II/III），养成深度与战力反馈同步拉长。

## 九、树形布局规范（参考 AL 学院科技树）

> **目标**：把每个分支抽象成**分层有向图（layered graph）**，给出确定性的层号、列号、连线点计算方式，使任何实现者都能无歧义地还原「根→分叉→收敛」的标准树形。

### 9.1 参考图结构抽象

从 `科技树.jpg` / `【AL】学院科技系统_V1.0.docx` 可以抽象出 6 条不变规则：

1. **一屏一主树**：顶部用页签切换 4 大分支；每个分支独占一屏，内部是一棵（或一片）自上而下的树。
2. **严格分层**：同一层的所有节点**水平对齐**（等 y）；父节点一定在子节点上方，不允许子节点比父节点高。
3. **直角连线**：父子之间只用「竖线 + 横线 + 竖线」三种线段，禁止斜线；多父/多子通过水平汇流/分流实现。
4. **避免交叉**：同一层内节点按 DFS 先序排列，使边尽量垂直；跨列边在层间隙处水平穿过，不与节点体重叠。
5. **层距充足**：相邻两层图标中心距 ≥ 图标高度的 1.3 倍，让折线清晰可见（沿用 v4.6 的 `rowH = NODE + 34×3`）。
6. **状态即颜色**：未解锁连线灰化半透明；已解锁连线取父节点图标色；MAX 节点带金色光晕；图标本身用锁态灰化。

### 9.2 我们天赋树的分层规划

| 分支 | 类型 | 层数 | 说明 |
|---|---|---|---|
| 根脉 | 6 根节点集合 | 1（或 2，加虚拟根） | 无前置，按 2×3 网格展示；如需更像树，可在顶端画一个不可点击的虚拟根节点线连 6 节点。 |
| 五行 | 5 棵并行子树（每棵单链） | 单棵 16 层 | 每元素一棵**垂直线性链**：核心 → 攻I → 防I → 血I → 暴I → 解锁Lv3 → 攻II → 防II → 血II → 暴II → 解锁Lv4 → 攻III → 防III → 血III → 暴III → 解锁Lv5。5 棵子树并排成 5 大列（对应手机竖屏一行 5 图标上限）。 |
| 防御 | 1 棵收敛树 | 7 层 | 5 个基础 I 节点为根 → 解锁Lv3 → 2 个进阶 II → 解锁Lv4 → 1 个进阶 III → 解锁Lv5 → 1 个顶石。 |
| 统御 | 真前置树（v4.9） | 3–4 层 | 火 4 根（攻/防/血/暴·火）→ 金木土水各 4 节点（前置含火系同名根）→ 全系通晓（前置火 4 根）。v4.9 起数据已有内部前置，不再依赖视觉骨架。 |

### 9.3 节点排布算法

对某个分支 `B`：

```text
1. 取分支内所有节点 N。
2. 建同分支邻接表：若节点 c 的 prerequisite 中包含 p，且 p∈N，则 p→c 是一条边。
3. 计算层号 tier(c) = 从任意无同分支前置的节点到 c 的最长路径长度。
   - 无同分支前置：tier = 0。
   - 有多个同分支前置：tier = max(tier(父)) + 1。
4. 同层节点排序（减少交叉）：
   a. 按 DFS 先序给每个节点一个序列号；
   b. 同一 tier 内按序列号从左到右排列。
5. 列号计算：
   - 每个分支页总宽 = screenWidth - 左右边距。
   - 若分支是「五行」这类多子树森林，先把总宽按子树数量切分（5 等份），再在每份子树内部按最多子列切分。
   - 若分支是「防御」单树，按该层最大节点数均匀分布列。
   - 节点水平居中：x = 左边界 + (col + 0.5) × colWidth。
6. y 计算：y = 顶部预留区（子页签高 + 标题高）+ tier × rowH。
```

**关键细节**
- 多父节点：子节点放在最深父节点所在层的下一层；浅父节点的连线会「向下走一段再横向汇入」。
- 五行单链：每元素列内为 1 子列垂直线性链，无横向分叉，天然无交叉。
- 防重叠：若某层节点数过多导致列宽 < 最小节点宽，则整体横向滚动（或该层节点换行），不要压缩节点到看不清。

### 9.4 连线与防交叉规则

所有边统一按以下优先级走线，代码实现时固定顺序，不要随机：

1. **同列父子**：父底边中点 → 子顶边中点，纯竖线。
2. **跨列父子（同一子树内）**：
   - 从父底边中点竖直向下到「父层底 + rowH/2」的汇流 y；
   - 水平横移到子列中点；
   - 竖直向下到子顶边中点。
3. **多子共享父**：先竖直向下到分叉 y，再分别水平分岔到各子列，再竖直下落到各子顶。分叉 y 取所有子节点顶 y 的上方 1/3 处。
4. **多父共享子**：各父线先各自下降到同一汇流 y（子节点顶 y 上方 1/3 处），水平汇到子列中点，再竖直下降到子顶。汇入顺序按父节点列号从左到右，避免交叉。
5. **跨子树/跨页依赖**：不画线（如 统御 依赖 五行 解锁Lv5、根脉 节点）。用锁态 + 弹窗前置条件文字表达。
6. **视觉分组线（仅统御历史形态）**：v4.9 起统御已有真前置树，可直绘真实连线；若仍想强调「类别→元素」骨架，可叠加浅灰虚线，与真实前置线区分。

**状态颜色规则（与 §八 一致）**
- 子节点未解锁：线 `rgba(128,128,128,0.35)`，2px。
- 子节点已解锁：线取父节点图标色（按元素/分支映射，见 `getNodeColor`），2px。
- 子节点 MAX：线末端加 4px 金色圆点。
- 所有线必须先于节点绘制，避免线压到图标上。

### 9.7 与子页签、滚动、命中的衔接

- 子页签继续沿用 v4.7 的顶部固定条（根脉 / 五行 / 统御 / 防御），切换时 `talentScrollY = 0`。
- 每个分支内部按本规范分层纵向滚动；若某层节点过多导致列宽不足，整体允许横向滚动（优先保证节点可读）。
- 命中框注册：仍按 `lM` 的 `x/y/size/id` 格式；节点位置按滚动偏移后计算。
- 点击命中逻辑不变：命中子页签 → 切页；命中节点 → 弹窗；未命中 → 开始拖拽滚动。

### 9.8 为什么这样能解决 AI「画不出树形」的问题

之前 AI 失败的核心原因通常是：
1. 没有显式给每个节点定 **tier + col**，导致节点上下错位；
2. 连线用斜线或贝塞尔，交叉后难以控制；
3. 多父/多子节点没有统一的汇流/分叉 y，线会穿过节点。

本规范把以上三点全部**算法化**：先算层、再算列、再用固定的「竖-横-竖」三段式走线，所有坐标由公式推导，不再依赖 AI 的「目测」。只要按表实现，就能稳定还原参考图效果。

## 十、生效时机与存档

- `applyTalentsToBattle()` 在 `startGame` 时调用，重建 `talentCombat` / `talentMods` 快照；对局内读取快照，不重算。
- `loadPlayerData` 按节点 id 合并存档；新 id 无存档则跳过，向后兼容。
- `isTalentUnlocked(id)`：空 `prerequisite` 或缺前置节点 → 解锁；任一前置等级不足 → 锁定（已修复崩溃 bug，见 §十二）。
- `claimTalent(id)`：倒计时结束点击节点角标时调用，执行 `level++` 并 `savePlayerData()` 落盘；`calculatePower` 实时变，`talentCombat` 快照在下一战 `applyTalentsToBattle` 重算生效（两段式计时的最终升级动作，见 §八）。

## 十一、与五行属性技能的关系

- 本天赋树的 `coeff_*` / `elem_def_*` / `elem_hp_*` / `elem_crit_*` 直接挂钩 `getElementBonus` 的五行伤害结算，是「属性技能」的养成放大器（详见 `docs/策划案/五行属性技能设计.md`）。
- `unlock_×_3/4/5` 控制对应元素技能卡的 Lv3–Lv5 是否进入三选一池，是天赋 → 技能的解锁闸门。

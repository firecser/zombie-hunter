# 埋点事件表（场景分析 · 微信官方）

> **入口**：微信公众平台 → **统计 → 场景分析 → 场景管理 → 新建场景**
> （不是「数据分析 → 自定义分析」，两套系统不同）

---

## 一、平台限制（先看这个）

| 项 | 限制 |
|---|---|
| 上报 API | `wx.reportUserBehaviorBranchAnalytics({ branchId, branchDim, eventType })` |
| `branchId` | 后台创建行为分支后，点「获取代码」分配 |
| `branchDim` | **只能是 1–100 的整数**（String），不能塞 `slot` 这种文本 |
| `eventType` | `1` = 曝光，`2` = 点击 |
| 数据延迟 | **T+1**（今天的数据明天看） |

所以我们用 **branchDim = 关卡号**（1–60，正好在范围内），点位靠 `branchId` 区分。

---

## 二、推荐建法：1 个场景 + 6 个行为分支

### 第 1 步：新建场景

| 字段 | 填什么 |
|---|---|
| 场景名称 | `广告点位` |
| 场景类型 | 游戏内复活/资源 |
| 参数设置 | ✅ 勾选「通过 branchDim 字段接受额外参数值」 |
| 参数名称 | `关卡`（1–100） |

### 第 2 步：建 6 个行为分支

在「其他行为」里填自定义名称，逐个「新建」：

| 分支名称 | 对应代码 slot | 触发场景 |
|---|---|---|
| 炸弹补弹 | `bomb` | 本局首次没炸弹时 |
| 盾兵援军 | `shield` | 护城格破损后盾兵出现 |
| 守将复活 | `revive` | 护城归零、守将出现 |
| 换一批 | `reroll` | 升级面板出现且还有刷新次数 |
| 宝箱翻倍 | `chest` | 拾取宝箱后出现 ×2 提示 |
| 双倍金币 | `double_gold` | 通关结算页 |

### 第 3 步：拿 branchId 填代码

每个分支点「获取代码」，复制出类似：

```js
wx.reportUserBehaviorBranchAnalytics({ branchId: 'AbCd1234', branchDim: "1", eventType: 1 })
```

把 `branchId` 填进 `game.js` 顶部的表：

```js
const AD_BRANCH = {
    bomb: 'AbCd1234',
    shield: '...',
    revive: '...',
    reroll: '...',
    chest: '...',
    double_gold: '...'
};
```

> 没填的分支不会上报，也**不会报错**——可以先上线，再补 ID。

## 三、代码已经埋好的位置

| 时机 | 事件 |
|---|---|
| 点位**出现** | `eventType = 1`（曝光） |
| 玩家**点击**（进入 `showRewardedAd`） | `eventType = 2`（点击） |

对应关系：

| 点位 | 曝光时机 | 点击时机 |
|---|---|---|
| 炸弹 | 关内首次 `bombCount<=0` | 点「看广告补弹」 |
| 盾兵 | 盾兵生成 | 点盾兵 |
| 复活 | 守将出现 | 点守将/复活按钮 |
| 换一批 | 每次升级面板生成 | 点「换一批」 |
| 宝箱 | ×2 胶囊出现 | 点胶囊 |
| 双倍金币 | 结算页出现 | 点「金币×2」 |

## 四、怎么读数据

| 现象 | 结论 | 动作 |
|---|---|---|
| **曝光高、点击低**（<15%） | 奖励不够诱人 / 玩家不需要 | 加码奖励，或换更痛的时刻 |
| **曝光低** | 点位几乎不出现 / 太隐蔽 | 放宽触发条件、增强提示 |
| **点击高、完播低** | 只是想试试，看到广告就退 | 检查广告时长/误触 |
| **复活点击 <30%** | 失败挫败感 > 继续意愿 | 降低难度或提高复活价值 |

> 场景分析只能看"曝光→点击"，**看完广告没看完**要看 `ad_result`（`wx.reportAnalytics`，需另外在「自定义分析」注册；不注册也不影响场景分析）。

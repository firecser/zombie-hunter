# 埋点事件表（场景分析 · 微信官方）

> **入口**：微信公众平台 → **统计 → 场景分析 → 场景管理 → 新建场景**
> （不是「数据分析 → 自定义分析」，两套系统不同）

---

## 一、平台限制（先看这个）

| 项 | 限制 |
|---|---|
| 上报 API | `wx.reportUserBehaviorBranchAnalytics({ branchId, branchDim, eventType })` |
| `branchId` | 后台创建行为分支后，点「获取代码」分配 |
| `branchDim` | **只能是 1–100 的整数**（String），不能塞 `slot` 这种文本 |
| `eventType` | `1` = 曝光，`2` = 点击 |
| 数据延迟 | **T+1**（今天的数据明天看） |

所以我们用 **branchDim = 关卡号**（1–60，正好在范围内），点位靠 `branchId` 区分。

---

## 二、推荐建法：**一个广告位一个场景**（6 个场景）

> 为什么不是"一个场景 + 6 个分支"？
> 因为官方把「广告点击 / 广告收入 / ARPPU / ECPM」挂在**广告行为（激励式广告）分支**上；
> 用「其他行为」建分支只能拿到曝光/点击，拿不到收入。
> 且 `branchDim` 只有一个数字，用「关卡」最有用（能看"第几关广告最值钱"）。

### 每个场景都这样填

| 字段 | 填什么 |
|---|---|
| 场景名称 | 见下表（**必须英文/拼音或中文都行，但要能对上 `AD_BRANCH` 的键**） |
| 场景类型 | 见下表 |
| 参数设置 | ✅ 勾选「通过 branchDim 字段接受额外参数值」 |
| 参数名称 | `关卡`（提示 1–100） |
| 广告行为 | ✅ **激励式广告**（其余 banner/插屏/格子/原生 **都不勾**） |
| 分享行为 | ❌ 不勾 |
| 其他行为 | ❌ 不建 |

### 6 个场景的具体填法

| # | 场景名称（建议） | 场景类型 | 对应代码 slot | 什么时候触发 |
|---|---|---|---|---|
| 1 | `炸弹补弹` | 游戏内复活/资源 | `bomb` | 本局没炸弹时点「看广告补弹」 |
| 2 | `盾兵援军` | 游戏内复活/资源 | `shield` | 护城格破损后点盾兵 |
| 3 | `守将复活` | 游戏内复活/资源 | `revive` | 城破后点守将复活 |
| 4 | `换一批` | 游戏内复活/资源 | `reroll` | 升级面板点「换一批」 |
| 5 | `宝箱翻倍` | 游戏内复活/资源 | `chest` | 拾到宝箱后点「看广告 ×2」 |
| 6 | `双倍金币` | **游戏后奖励结算** | `double_gold` | 通关结算页点「金币 ×2」 |

> 场景类型只是分类标签，不影响数据口径。选「游戏内复活/资源」和「游戏后奖励结算」是因为它们在报表里会分到两个板块，看起来更清楚。

## 二·补 三个上报时机（官方三连）

| 官方步骤 | 含义 | 我们的实现 |
|---|---|---|
| step1 广告前场景曝光 | 按钮/点位**出现** | `reportBranch(slot, 1)` —— 点位生成时 |
| step2 广告前场景点击 | 玩家**点击** | `reportBranch(slot, 2)` —— 进 `showRewardedAd` 时 |
| **step3 广告曝光** | 广告组件**真正播放** | **`ad.show({ branchId, branchDim })`** ← 这步不做，平台拿不到收入/ECPM |

> 第 3 步是官方文档里的 **关键要求**：不传 `branchId`，场景分析里「广告点击/收入/ECPM/ARPPU」全是空。

## 三、代码已经埋好的位置

| 时机 | 事件 |
|---|---|
| 点位**出现** | `eventType = 1`（曝光） |
| 玩家**点击**（进入 `showRewardedAd`） | `eventType = 2`（点击） |

对应关系：

| 点位 | 曝光时机 | 点击时机 |
|---|---|---|
| 炸弹 | 关内首次 `bombCount<=0` | 点「看广告补弹」 |
| 盾兵 | 盾兵生成 | 点盾兵 |
| 复活 | 守将出现 | 点守将/复活按钮 |
| 换一批 | 每次升级面板生成 | 点「换一批」 |
| 宝箱 | ×2 胶囊出现 | 点胶囊 |
| 双倍金币 | 结算页出现 | 点「金币×2」 |

## 四、怎么读数据

| 现象 | 结论 | 动作 |
|---|---|---|
| **曝光高、点击低**（<15%） | 奖励不够诱人 / 玩家不需要 | 加码奖励，或换更痛的时刻 |
| **曝光低** | 点位几乎不出现 / 太隐蔽 | 放宽触发条件、增强提示 |
| **点击高、完播低** | 只是想试试，看到广告就退 | 检查广告时长/误触 |
| **复活点击 <30%** | 失败挫败感 > 继续意愿 | 降低难度或提高复活价值 |

> 场景分析只能看"曝光→点击"，**看完广告没看完**要看 `ad_result`（`wx.reportAnalytics`，需另外在「自定义分析」注册；不注册也不影响场景分析）。

## 六、已知取舍（v2.22.5）

`ad.show({ branchId, branchDim })` 是官方推荐写法，但实测部分基础库传参后会出现**广告播完不发奖 / 拉不起广告**。

因此代码里加了开关：

```js
const USE_SCENE_SHOW_ARGS = false;   // 默认关闭，功能优先
```

| 开关 | 效果 |
|---|---|
| `false`（当前） | 广告稳定播放、发奖正常；场景分析能看「曝光/点击」，**看不到广告收入/ECPM** |
| `true` | 收入归因完整；但可能触发播放异常（需真机验证） |

验证方法：真机把开关改 `true`，跑 3 局；只要有一次"播完不发奖"，就保持 `false`。

## 七、已知噪音：`removeTextView:fail xxx not found`

播放激励视频时控制台刷这个错误，是**微信 SDK 内部**在广告视图销毁时找不到 textView 导致的，社区确认**不影响功能**。

已知诱因：
1. 反复 `onClose` / `offClose`（我们在 v2.23.1 已改为**只注册一次**）
2. 广告期间调用原生 `wx.showToast`（已改为画布内提示）
3. 手动 `ad.destroy()`（我们没有调用）

如果仍出现，可以忽略；若伴随"广告黑屏/白屏"，才是真问题。
